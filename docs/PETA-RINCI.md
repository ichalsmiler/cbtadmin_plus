# CBT Admin Plus — peta RINCI (dibaca hanya bila perlu; ringkasannya di CLAUDE.md)

Panel admin ujian CBT (CodeIgniter 4.7, PHP 8.4) di atas **Moodle 5.1.8+** (kode web di `public/`).
Meniru AIOCBT CBTAdmin (lms.sman2makassar.sch.id/cbtadmin). Semua teks UI berbahasa Indonesia.
Repo `ichalsmiler/cbtadmin_plus` (lokal `F:/apps/cbtadmin_plus`) = cbtadmin + Konvert User (dulu repo `web-ujian`) di folder `konvert/`.
Repo lama `cbtadmin` dan `web-ujian` tidak dipakai lagi untuk fitur baru.

## Struktur kode panel (`app/`)
- `Controllers/PanelController.php` — basis: `render()`, `myRuang()` (ruang pengawas), `ruangList()`, `VERSION`;
  pengawas hanya melihat/menindak siswa ruangnya di sesi aktif: `siswaSesi()`, `saringSesi($rows)`, `moodleIdsSesi()`
  (Peserta ruang, Status Peserta, Login ganda, Reset Login, Blokir Siswa); tanpa sesi aktif daftar kosong + peringatan
  di layout (`sesiBelumPengawas`); `Tingkat::dariRequest()` pengawas bawaan = tingkatan sesi aktif.
- `Filters/Guard.php` — login, CSRF, timeout, role. `PROKTOR_PATHS` = menu yang boleh untuk pengawas (role `proktor`).
  Sesi dicap `cred` = `Guard::cap(password_hash)` (diisi di Auth, Tukar Akses/kembali, Ganti Password, ubah akun sendiri);
  password/kode diganti → sesi lama ditolak. Proktor tanpa ruang → `admin_ruang`=0 (tanpa siswa, token terkunci). Pengawas (role proktor) maksimal 2 perangkat (`Guard::MAKS_PERANGKAT`, 23 Nov 2026; dulu 1): tiap login menambah token 30 hex ke `admins.sesi_token` (dipisah koma, terlama di depan, `Guard::tokenPerangkat()`; VARCHAR 64 cukup untuk 2 token) + sesi `sesi_token`, login ke-3 membuang token terlama → sesi perangkat itu ditolak Guard ("sudah login di 2 perangkat lain"); logout melepas tokennya sendiri; sesi pengawas berakhir setelah 30 menit diam (`Guard::TIMEOUT_PENGAWAS`; peran lain `cbt.sessionTimeout`), pembaruan otomatis dashboard/token ikut dihitung aktivitas khusus pengawas (dashboard terbuka = sesi tetap hidup); diuji curl dengan akun sementara; Tukar Akses dikecualikan; role `demo` (Tools → Akun → Role "Demo (pengawas contoh)" + pilih "Pakai data ruang" → ruang_id) = pengawas contoh: admin_ruang dari ruang_id, menu pengawas, tidak dibatasi jumlah perangkat, bukan pengawas resmi ruang (tidak muncul di Daftar Ruang), ikut terhapus bersama ruangnya), log `login_perangkat_lain` (tampil di Log → Pengawas).
  Simpan absensi pengawas hanya untuk siswa sesi aktif. Jembatan `create_users` menolak admin situs/guest Moodle.
- `Views/layout/main.php` — array `$menu` sidebar; admin menyembunyikan `token`,`kehadiran`; Reset Login muncul
  hanya bila setting `lock_login`=1. Tombol "Kembali ke Admin" saat Tukar Akses (`session tukar_dari`).
- `Config/Routes.php` — semua rute (grup terfilter Guard).
- `Config/Registrar.php` — baseURL disusun dari skema (HTTPS / X-Forwarded-Proto) + host permintaan (+ allowedHostnames); karena .env dibaca CI SETELAH registrar, nilai env `app.baseURL` diganti per permintaan ($_ENV/$_SERVER/putenv). Jadi CSS/JS/tautan mengikuti alamat yang dibuka (http IP lokal atau https domain Cloudflare).
- JS `public/assets/js/panel.js`: `data-post`+`data-fields`+`data-confirm-text` (POST via `#postForm`),
  `data-confirm-button` (form massal), `data-fill-modal`+`data-fill` (isi modal), `table.datatable` (DataTables; isi tbody disembunyikan sampai siap: `html.js` dari `partials/tema_awal` + kelas `.dt-siap` dari panel.js,
  `data-order-col`), `a[data-pdf]`/`form[data-pdf]` (pratinjau PDF di `#pdfModal`, Unduh = `?unduh=1` → attachment
  di `Pdf::respond`; `?cetak=1` = HTML siap print browser tanpa dompdf, gambar via `tools/gambar/*`, dipakai tombol Cetak
  Kartu Peserta (`data-no-pdf`) dan Cetak ID Login). CSS `public/assets/css/panel.css` (token warna terang/gelap di `:root` dan `[data-bs-theme=dark]`; arah desain di `DESIGN.md`: sejak 2.6.9 palet (2.6.10 font Figtree) Dens-UI (Mars Green #00797A/#19A3A4 + satu aksen oranye, netral kehijauan, radius .875rem, bayangan `--shadow-panel` di kartu), tema bawaan terang, font Figtree/JetBrains Mono (woff2 variabel) lokal di `public/assets/fonts` (OFL); Konvert memakai token dan font yang sama, kaca hanya bilah atas + `.token-card`, kartu statistik `stat-netral|proses|ok|awas|redup`; tema disimpan `localStorage cbt-tema`, dipasang `partials/tema_awal`, tombol `[data-tema-toggle]`).
- Server utama RAM 1 GB: dompdf maks ±400 kartu per PDF (`Dokumen::MAKS_KARTU`, lebih → daftar tautan per
  ruang/kelas `dokumen/kartu_bagian`); gambar di PDF besar pakai path berkas (chroot `writable/uploads`), bukan data-URI.
- Kartu per File (ZIP) `dokumen/cetak_doc/kartu_zip`: satu PDF per kelas/ruang (`Pdf::render`) dalam ZIP; "Semua kelas/ruang (N)" dihitung JS dari `data-jumlah` sesuai Tingkatan. Tombol berputar sampai selesai: cookie `kartu_zip=<token>` ATAU tanda cache server `kartu_zip_<admin_id>_<token>` (10 menit) yang ditanya JS tiap 2 detik lewat `dokumen/cetak_doc/zip_status?token=` (cookie tidak sampai bila unduhan diambil alih IDM dsb.).
- Dokumen → Rekap Simulasi `dokumen/rekap_simulasi` (`RekapSimulasi`, view `dokumen/rekap_simulasi`): pilih kategori ujian Moodle (bawaan: nama berisi "SIMULASI", lalu tes aktif; SESI NONAKTIF tidak tampil) + mapel (kosong = semua quiz di kategori) + Tingkatan; siswa dari Data CBTAdmin (username → id Moodle), status per siswa dari mdl_quiz_attempts (preview 0): finished = Sudah ikut, lainnya = Belum selesai, tanpa percobaan / akun Moodle belum ada = Belum ikut; tabel per kelas (jumlah, %, progress, <details> nama yang sudah + waktu kirim terakhir `selesai_pada`, <details> nama yang belum) + kartu statistik; Export Excel `dokumen/rekap_simulasi/export` 3 lembar (Ringkasan, Sudah ikut + Selesai pada, Belum ikut), nama berkas `rekap_simulasi_<nama>_kelas_<T>.xlsx`. Akses: admin/operator (Guard `dokumen*`).
- Setting Ujian: pilihan "Semua Sesi" (`ActiveTest::SEMUA` = -1, `sesiPilihan()`) di paling bawah; siswa tidak disaring sesi (`sesiFilter()` = null).
- Partial `Views/partials/filter_tingkat.php` (select Tingkatan X/XI/XII lalu "Semua", `Libraries/Tingkat.php`);
  `Tingkat::dariRequest()` bawaan X, pilihan diingat di sesi `filter_tingkat` (dipakai juga ekspor tanpa ?tingkat=).
  Urutan filter di semua halaman: Tingkatan → Kelas → Ruang. panel.js menyaring `#fKelas` menurut `#fTingkat` dan
  `#fRuang` (opsi `data-kelas`, dari kolom `kelas` di `PanelController::ruangList()`) menurut kelas/tingkatan.

## HA: tombol Kembalikan (failback tanpa tukar ha.conf, 21 Nov 2026)
- Peran: utama | cadangan | nonaktif (utama lama / cadangan yang dibekukan) | kembali (utama sedang mengambil data).
  Halaman siaga membuka `/cbt-ha-*` (peran + status) untuk pasangan; install.sh menambahkannya ke snippet lama.
- Server utama nonaktif: menu Server Cadangan → kartu hijau "Kembalikan ujian ke server ini" (ketik KEMBALIKAN, tombol
  terkunci bila kontak > 3 menit) → `cbt-ha-panel kembalikan` (cek pasangan = utama) → `ha-utama.sh kembalikan`
  (latar belakang, log sama dengan pindah). Konsol: `cbt-ha kembalikan`.
  Langkah: peran `kembali` → tunggu `/cbt-ha-kembali` di cadangan `siap` (≤15 mnt; `tolak …` → batal) → backup DB lama
  `/var/backups/cbt/db/sebelum-kembali-*` → rsync modul `kembali` (db.sql.gz, --add-drop-database moodle cbtadmin) →
  impor → rsync moodledata + uploads → read_only 0, cron, peran utama, purge cache. Gagal → peran nonaktif lagi.
- Cadangan: `cbt-ha-jaga` versi cadangan (ha-cadangan.sh `tulis_jaga`, cron `/etc/cron.d/cbt-ha-jaga`, flock):
  utama+pasangan kembali → tolak bila quiz_attempts inprogress / settings sesi_aktif, selain itu bekukan (read_only,
  cron mati, halaman "Ujian kembali ke server utama", peran nonaktif, dump ke /var/lib/cbt-ha-kembali, rsyncd modul
  moodledata/cbtupload/kembali untuk 10.77.0.1, status `siap`); nonaktif+pasangan utama → `ha-cadangan.sh pasang`
  otomatis (YES=1, flock /run/cbt-ha-pasang.lock, log /var/log/cbt-ha-kembali.log); nonaktif+pasangan nonaktif →
  cairkan (aktif lagi). `cbt-ha batal` di cadangan = cairkan + tolak permintaan 15 menit.
- Utama: jaga mengubah sisa peran `kembali` tanpa proses (pgrep) jadi nonaktif. Cron jaga kini `/etc/cron.d/cbt-ha-jaga`.
- Berlaku setelah cbt-perbarui di kedua server, lalu `cbt-ha utama` (server utama) dan `cbt-ha cadangan KODE` (cadangan).
  Diuji 21 Nov 2026 cbt162 (nonaktif) ← VPS (utama): 5 langkah ±1 menit, VPS terpasang ulang cadangan otomatis
  (replikasi Yes/Yes, lag 0). Pasang pengaman tanpa data: `ha-utama.sh jaga` / `ha-cadangan.sh jaga` (install.sh otomatis;
  jenis = ada cron cbt-ha-cadangan). Cek pengecualian siaga pakai `grep -F "^/cbt-ha-)"` (komentar memuat "cbt-ha-").
